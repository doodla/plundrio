# v0.12.1

Mobile layout fixes for the web dashboard. v0.11.0 shipped the dashboard desktop-first and the v0.12.0 mobile pass (#27) reflowed the chrome — top rail, bottom tab bar, account cluster — but left the Deck's master panel and the log console untouched, so on a phone the hero card and logs ran off the right edge.

## What was wrong

The Deck's `.panel` is a `400px 1fr` two-column grid (hero bay | account). The mobile breakpoint never collapsed it, so the panel and its children kept a desktop width (~573px) inside a ~390px viewport; `main`'s clipping hid the page scroll but cut everything past the edge. The root inflator was the bay's `white-space:nowrap` transfer title — its ~540px min-content sized the `1fr` (= `minmax(auto,1fr)`) track, so even collapsing to one column didn't help until the track was made shrinkable.

## Fixes (all scoped to `@media (max-width: 560px)`)

- **Deck master panel** collapses to a single column via `minmax(0, 1fr)` (not `1fr`) plus `min-width: 0` on the bay, so the track can shrink below the title's min-content and the title's existing ellipsis engages. The bay's divider moves from right edge to bottom now that it stacks above the account cluster.
- **Transfer hero**: the two phase panels (`.legend`) stack to one column; the gauge key chips (`.fgKeys`) wrap; the flow-gauge SVG (viewBox-only, intrinsic ~419px) scales to its container.
- **Log console** (shared by Deck + Logs): log lines drop the level/component columns and **wrap** the message instead of one-line ellipsis (logs are for reading), with `minmax(0,1fr)` so nowrap content can't inflate the track; the filter bar wraps on very narrow phones.

Verified with live data at 390px and 320px across Deck, Account, Logs, and Settings — no horizontal scroll on any page. Desktop layout is unchanged (every rule is inside the mobile breakpoint).
