# v0.12.0

First release after the v0.11.0 web dashboard. Hardens the put.io API path against rate limits, makes failures legible to the *arr stack, polishes the dashboard for mobile, and closes a batch of small correctness gaps surfaced by a large new test pass.

## Features

- **put.io 429 handling (#28).** API calls now retry on HTTP 429 with exponential backoff + jitter instead of failing the transfer outright. put.io rate-limits under load; previously a 429 bubbled up as a hard error and the *arr client saw a stalled download.
- **put.io errors surfaced as Transmission `errorString` (#22, #29).** When put.io reports a transfer error, the message is now passed through to Sonarr/Radarr via the Transmission RPC `errorString` field, so the failure is visible in the *arr queue instead of presenting as a silent stall.
- **Mobile-friendly dashboard (#27).** The v0.11.0 dashboard layout now adapts to small screens.

## Fixes

- **Graceful shutdown.** A clean shutdown no longer calls `log.Fatal`; the server drains in-flight work and exits 0, so `docker stop` / `compose down` is no longer logged as a crash.
- **Atomic, serialized config writes.** Dashboard-driven setting edits write through a single shared atomic-write path (`atomicfile.WriteFile`) using a unique temp file, and `WriteOverride` is serialized to prevent concurrent edits from clobbering each other (lost updates).
- **Zero-division guards.** Download-rate computation guards against zero elapsed time and the disk-quota check guards against a zero reported disk size — both previously could divide by zero on edge timing / unusual put.io responses.
- **`get-token` resilience.** A transient poll error during device-code auth no longer aborts the whole token flow.
- **Cancellable retry backoff.** Retry backoff sleeps now honor context cancellation and skip the wasted final sleep after the last attempt.

## Under the hood

- New `internal/atomicfile` package consolidates three previously-divergent atomic-write implementations.
- New `internal/api/ratelimit.go` carries the 429 retry/backoff logic.
- Substantial new test coverage across api, config, download, and server (including end-to-end tests against an `httptest` put.io); `go test -race ./...` is green.
