# v0.10.12

## What changed

Multi-file put.io transfers with two distinct files sharing a basename now download to distinct local paths. Previously, the recursive walk in `GetAllTransferFiles` flattened put.io's directory tree and dropped each file's parent context, so leaves like `S01E01/2_English.srt` and `S01E02/2_English.srt` collapsed onto the same target — first download wins, every subsequent one fails inside grab's `validateLocal` with `ErrBadLength` and the transfer never finishes.

## Why

Observed in production on transfer 105269882 (`Reborn.Rich.S01.KOREAN.1080p.WEBRip.x265[eztv.re]`, 32 files / 16 MP4s + 16 per-episode subtitle subdirs) on 2026-05-06: 17 of 32 files completed (the MP4s plus the first `2_English.srt` to land), the remaining 15 subtitles permanently failed with identical `target_path` in every retry log line. Identical-basename collisions inside subdirectories aren't rare in scene release packs, so the bug was reproducible across the catalog.

## Visible behavior

None for typical setups. Internally:

- `GetAllTransferFiles` now returns `[]api.TransferFile` (file + forward-slash relative path from the transfer root) instead of `[]*putio.File`. Per-file logs gain a `rel_path` field where applicable.
- Download progress and worker logs now carry `file_id` alongside `file_name`, so two distinct files with the same basename are distinguishable in the log stream.

## No migration needed

Container restart picks up the new behavior. No config changes, no state file changes.
